# API

> **Status: preliminary.** The API is largely **auto-generated by PostgREST** from
> the database schema, so there is no hand-written endpoint contract yet. This
> document describes the intended surface and conventions. Firm it up as
> implementation proceeds.

## How the API works

Supabase exposes the database through **PostgREST**: tables, views, and functions
become REST endpoints automatically. Access is governed by **RLS** based on the JWT
(or the anon key for public access). This means "what the API allows" is defined
mostly by the schema and its RLS policies (see `DATA-MODEL.md`, `SECURITY.md`), not
by bespoke controllers.

## Auth

- **Anonymous public**: uses the Supabase **anon key**. Can insert reports and flags,
  and read `public_reports` — everything else is blocked by RLS.
- **Association / Administrator**: authenticate via GoTrue, receive a JWT; RLS grants
  role-appropriate access. Short-lived tokens + refresh (RNF34).

## Main operations (intended)

| Operation | Who | Backed by |
|---|---|---|
| Create report | anon | `INSERT` into `reports` (triggers validate) |
| File a flag | anon | `INSERT` into `report_flags` |
| Read public map data | anon | `SELECT` on `public_reports` view |
| Get map clusters | anon | RPC → `get_report_clusters(eps_meters)` |
| Read full reports | Association/Admin | `SELECT` on `reports` (RLS) |
| Export data | Association | `SELECT` + client-side CSV/Excel (RF17) |
| Hide/delete/restore report | Admin | `UPDATE` on `reports` (+ audit log) |
| Review duplicate queue | Admin | `SELECT`/`UPDATE` on `duplicate_candidates` |

## Conventions to define later

- Exact PostgREST query/filter patterns the app will use per screen.
- Any custom RPC functions beyond `get_report_clusters` (e.g. export helpers).
- Storage upload flow for photos (signed URLs vs. direct anon upload with server-side
  validation per RNF32).
- Error response shapes surfaced to the app (esp. trigger rejections: out-of-zone,
  invalid form structure).

## Notes

- Report creation must succeed **offline** in the app and sync later; the API is only
  hit on reconnect (RNF12). Design idempotent sync using the client-generated UUID.
- Confidence scores are computed **server-side** (trigger or Edge Function), not
  accepted from the client (RNF28).
