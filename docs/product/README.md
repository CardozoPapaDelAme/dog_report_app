# Product Documentation

This index owns product-document navigation. Product authority comes from the
approved clarifications followed by normative SRS v2; the remaining files help
readers find context without redefining those decisions.

## Read in this order

1. [`APPROVED-CLARIFICATIONS.md`](APPROVED-CLARIFICATIONS.md) — approved amendments; later decisions supersede earlier conflicts
2. [`ETAPA1-REQUERIMIENTOS-V2.md`](ETAPA1-REQUERIMIENTOS-V2.md) — normative consolidated SRS
3. [`ETAPA1-REQUERIMIENTOS.md`](ETAPA1-REQUERIMIENTOS.md) and the PDF — historical wording and exact identifiers
4. [`PROBLEM-CONTEXT.md`](PROBLEM-CONTEXT.md) — problem, stakeholders, and current gap
5. [`VISION.md`](VISION.md) — desired outcomes, principles, and success
6. [`HIGH-LEVEL-REQUIREMENTS.md`](HIGH-LEVEL-REQUIREMENTS.md) — capability-level orientation
7. [`SOLUTION-EXPLORATION.md`](SOLUTION-EXPLORATION.md) — alternatives considered
8. [`ROADMAP.md`](ROADMAP.md) — phases, dependencies, and exit gates
9. [`GEOFENCE-CANDIDATE.md`](GEOFENCE-CANDIDATE.md) — candidate provenance and approval procedure

The original SRS body is never rewritten to conceal later decisions. Approved
clarifications and SRS v2 govern implementation. Requirement IDs remain exact and map many-to-many through
[`../TRACEABILITY.md`](../TRACEABILITY.md).
